What the system contains

Every figure is measured from the files on disk by the build scanner; the same index drives the desktop app, the installable app and this page.

What these builds actually are

Source scaffolds, not playable games — measured from the deployed files: the platform's compiled dist/ is 34 modules totalling 7 KB (211 bytes on average), and no tree contains a JavaScript bundle larger than 25 KB, so there is no production web build to run. This system faithfully indexes and ships those sources. It is a launcher and an index, not a game download.

These binaries are unsigned

No code-signing certificate is configured, so Windows SmartScreen will warn on first launch. Compare the SHA-256 above against SHA256SUMS.txt before running them.

How the pieces fit

One interface source, three delivery targets, and a verification pass that runs against the built files rather than the source.

One source of truth

The portal interface lives once in portal/. The installable app under pwa/ is generated from it, so the two can never disagree.

Measured, not asserted

The scanner reads the payload and emits the index — file counts, module sizes, document lists and SHA-256 digests of whole trees.

Offline by construction

The service worker precaches every shipped file under a content-hashed cache name, so a new build can never serve a stale mix.

Verified on the artifact

The packaged app is self-tested across three viewports, and the web app is audited by shutting its server down and reloading purely from cache.
